# 更新记录

## 1.7 · 整面透镜折射，取代固定四边彩边

- **重做光学模型：从「边缘彩边 + 中心全空」改为「整面凸透镜」**。此前折射只画在圆角/四边的窄带（固定青/品红双描边），中心 alpha 约 1/255 完全空白，用户反馈"四边固定很难看、中间没有折射"。现把整个表面当作一个有轻微曲率的透镜：中心保留柔和tilt，能接住随光照移动的大面积反光，整块玻璃都有自然的镜面流动感。
- **色散不再固定在四边**：由"钉死在圆角的青外品红内双色带"改为"随光照漂移的柔和光谱渐变 + 极轻的边缘条纹"，边缘更干净，主视觉交给中心流动反光。
- **高光随光照移动**：叠加"覆盖全面的稳定底光" + "跟踪光源的移动高光"，实测内部面亮度重心随指针从左 `0.464 → 0.519` 移动；四种棚灯反射与焦散仍随指针/滚动/拖拽变化。
- **保持通透与可读**：中心 alpha 约 88/255（有玻璃感但不糊内容），整个面 100% 有玻璃覆盖，0 过曝，色散通道跨度 0..75（柔和）。软件路径与 WebGL shader 严格同步；安卓 WebView 仍强制软件 2D 路径（沿用 1.6 的 GL 空层修复）。
- 离线光学实验脚本 `tools/art/glass-lab.cjs` 与验证脚本 `tests/ui/verify-android10.cjs`（新增高光移动、全face覆盖、0过曝断言）。

## 1.6 · 修复安卓真机「玻璃发平、看不到折射」

- **定位到真正的真机故障根因**：此前所有光学验证都在无 WebGL 的 Chromium 里进行，测的全是软件 2D 路径；而安卓 WebView 里 WebGL 上下文能创建成功、shader 也能编译通过，但合成到屏幕的是**全透明**画面。旧逻辑只要 WebGL program 存在就永远走 GL 分支，`software()` 从未被调用，于是真机上整层折射是空白——用户看到的就是"平的、没有折射"。这是 1.5 只加能力探测却没解决的问题（1.5 在真机上依旧走 GL 空层，故"一点变化也没有"）。
- **安卓 WebView 强制软件光学路径**：新增 `forceSoftware`，凡 UA 含 `Android` 或 `; wv)` 的引擎一律跳过 WebGL 初始化，直接走已被逐像素验证能画出折射的 2D 软件路径。桌面 Chromium 仍保留 WebGL 作为加分项。验证脚本用 Playwright 钩子记录 `#dock-optics.getContext()`：安卓 UA 下实际调用序列为 `['2d']`，WebGL **从未被请求**，彻底绕开 GL 空层。
- **明显增强色散可见度**：青/品红色散带加宽、饱和度与 alpha 贡献提高（WebGL shader 与软件路径同步）。安卓软件路径实测左右圆角青色带 `b-r` 峰值 166/185、品红带 -68，肉眼清晰可辨；中心 alpha 仍为 1/255 保持全透。
- 复现脚本 `tests/ui/verify-android10.cjs` 更新为「安卓 UA + WebGL 可用」场景（正是漏测的真机条件），除降级断言外新增 GL 未调用、青/品红双色带可见的强校验。

## 1.5 · Android 10 WebView 兼容加固

- **修复老 WebView 上玻璃失去饱和度的问题**：此前 `backdrop-filter: url(#glass-refract) saturate(106%)` 把 SVG 折射与饱和度写在**同一条声明**里。Android 10 出厂 WebView（Chromium 74）能解析 `backdrop-filter` 但不把 SVG 滤镜当作 backdrop 渲染，于是整条声明被丢弃，连 `saturate` 一起失效。现把饱和度拆成独立声明——任何支持 `backdrop-filter` 的引擎都能保住通透玻璃；`url()` 折射作为加分项单独处理。
- **能力探测替代 `@supports` 门控**：新增一次性 WebView 能力探测，读取 UA 版本与 `CSS.supports` 结果，给根节点标记 `glass-probed` / `glass-legacy-webview` / `glass-bdurl` / `glass-no-bd`。真实背景位移折射只在确认支持且非旧版 WebView 时启用；`@supports` 只校验语法、无法判断能否渲染，曾导致声明被丢弃时连累饱和度。完全不支持 `backdrop-filter` 的引擎改走更清晰的渐变描边，中心保持全透。
- **不依赖 WebGL 的折射基线**：安卓 WebView 中 WebGL 常不可用或丢失，canvas 软件光学路径始终是兜底。合成层测试在无 WebGL 的 Android 10 UA 下确认：canvas 折射正常绘制（边缘含色散彩色、中心 alpha 1/255）、saturate 保留、无 `url()` 声明、0 JS 错误；滑块拖动吸附、点击切换、胶囊拖拽回归通过。
- 复现脚本：`tests/ui/verify-android10.cjs`（Android 10 WebView 74/无 WebGL 与现代引擎两套场景）。

## 1.4 · 整块通透玻璃与光学折射

- 底部导航按真实清透玻璃重做：菲涅尔反射率在正对的中心约为 4%（几乎全透，身后内容清晰可见），只有圆角斜面与光源方向出现清晰镜面高光，并保留边缘 RGB 色散。移除了会把中心蒙白的 body 基础着色与环境底光，也移除了把高光扭成波纹的 SVG 湍流位移滤镜——二者此前让玻璃显得不透明、反射发糊。
- **彻底解决「不通透」**：定位到 canvas 之外的两层 CSS 才是主因——`backdrop-filter: blur(7px)` 把身后内容糊成一团（棋盘条纹对比度从裸基准 33.7 掉到 8.7），选中滑块 94% 白的不透明药丸盖住整个标签位。现移除背景模糊（仅保留极弱 `saturate(106%)`）、把白底与选中滑块降到近乎透明；玻璃本体改由增强后的 canvas 菲涅尔边缘高光与内阴影描边来呈现，中心保持全透。量化保真度（与无遮挡棋盘的相关性）从 **0.173 提升到 0.931**。
- 反射分布：软件路径分区实测中心平均 alpha 1/255、整体平均 8，0 过曝；反射集中在掠射边缘，中心通透，边缘高光足以在浅色页面上勾勒出玻璃轮廓。
- **可见的真实折射（重做）**：前一版只靠 `backdrop-filter:url()` 位移背景——浅灰纯色背景被位移后肉眼根本看不出，等于没有折射。改为在 canvas 光学层直接绘制折射本身：圆角处**青/品红色散边**（外青内品红）、紧贴边缘的**亮唇 + 内侧暗线**（光线弯折/全反射）、底缘**焦散亮弧**，中心保持通透。这些特征由玻璃自身绘制，任何背景（含纯色）下都可见；WebGL 与软件路径同步实现。同时保留 `backdrop-filter:url(#glass-refract)` 的内联 SDF 位移贴图，在支持的 WebView 上对真实背景再叠加透镜弯折；不支持时静默退化、不影响 canvas 折射。折射色散以独立加色层与自身 alpha 输出，避免被 4% 菲涅尔衰减淹没；0 过曝、中心 alpha 1/255。
- **可拖动的玻璃滑块（力度变形 + Q弹）**：按住选中滑块可沿导航栏左右拖动（钳制在胶囊内、松手吸附到最近标签，点击切换仍正常）；滑块是叠在导航玻璃之上的第二层独立玻璃。缩放与形变随拖拽力度非线性变化——小幅拖放大约 1.15、大幅拖放大到 1.43，并沿拖动方向拉长、垂直压扁（果冻感）。双欠阻尼弹簧（ζ≈0.3）让松手明显回弹：实测 sx `1.33 → 0.87 → 1.05 → 1.0`，多次振荡后归位。**修复 bug**：命中判定改用滑块实时 `getBoundingClientRect()`（含放大后的 transform），放大状态下抓滑块边缘不再误触发胶囊形变；钳制预留放大余量，圆角不被裁切。
- 本次反馈面板新增「复制」按钮，可将结果文本复制到系统剪贴板；Web 环境不可用时回退为长按手动复制提示。
- 说明：`filter:url()` 对 backdrop 透出的 DOM 无效（已实测），`backdrop-filter:url()` 在 Chromium 144 能位移背景但 Android WebView 版本支持不一、且纯色背景位移不可见。因此折射的主视觉由 canvas 自身绘制（任何背景可见），背景位移仅作加分；透射由 backdrop-filter 负责。

## 1.3 · 液态玻璃光学与四向弹性

- 导航玻璃反射按液态玻璃的光学方式重做：低粗糙度的窄棚灯高光只出现在圆角斜面上，平面中心保持通透以保证文字可读；加入 Schlick 菲涅尔色散，掠射角的红绿蓝通道轻微分离，形成真实的透镜彩边。软件渲染路径同步实现。
- 修正此前反射过曝、整片发白的问题：收敛环境与高光增益、缩窄高光带，高光随指针和滚动变化但不再淹没内容。
- 拖拽弹性改为四向：上下左右及斜向拖动都会沿拖拽轴非线性拉伸（橡皮筋饱和 + 二次幅度），交叉轴轻微压缩；形变幅度收敛到 5–9%，松手为带一次过冲的欠阻尼弹簧回弹。轻触仍切换标签，减少动态效果时直接归位。

## 1.2 · 明亮玻璃与弹性导航

- 整体界面从深夜暗色改为清新的亮色玻璃质感：冷白雾面背景、白色磨砂卡片、深墨色文字与青绿强调色；开屏同步改为冰白/青绿，保留原有动效时长与轻触跳过。文字对比度达到 WCAG 要求。
- 底部玻璃导航重新调校反射：四组棚灯光源、天空/冰面环境反射梯度与边缘高光，指针与滚动都会改变反射；旧版 WebView 使用等价的软件渲染路径。
- 导航新增拖拽弹性交互：横向按住拖拽时胶囊按阻尼弹性拉伸并剪切形变，松手后带过冲的弹簧回弹归位；超过阈值才视为拖拽，轻触仍正常切换标签，关闭动态效果时直接归位。
- 保留 Android 10（WebView 74）兼容回退、减少动态效果、无障碍受控操作与四边任务波纹。

## 1.1 · 光学导航与启动体验

- 以悬浮玻璃胶囊替代原先通栏的不透明底部导航。胶囊外侧不绘制背景，内部透出页面；支持的 WebView 使用真实背景模糊和饱和度调整。光照层根据曲面法线与虚拟棚灯计算视角反射，不采集现实环境图像。

- 收紧技能文件版本验证，拒绝字符串或小数伪装的版本号。保留 14 个内置技能、用户监督的手机操作和自带密钥的模型/搜索配置。
