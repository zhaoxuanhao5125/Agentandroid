## 3.2 · 多会话、本地保存、快捷提问与消息操作

## 3.0 · 对话式指挥台（问 / 谋 / 造）

- **指挥台改为豆包式对话框。** 任务指令表单换成消息流：用户气泡、助手气泡、打字指示器与空状态引导；底部输入框支持 Enter 发送、Shift+Enter 换行；对话历史在界面内维护，发送时随请求传给模型形成多轮上下文。保留品牌头图与液态玻璃底栏。

  - **问（Ask）**：直接回答，纯文本，不生成动作、不操作手机；独立系统提示强调无法看屏、不宣称已操作。

- **回归与兼容。** 保留既有技能库、连接、设备页与全部桥接操作；技能可作为对话的风格指引选用；更新 UI 回归以覆盖对话发送语义。同签名证书可覆盖安装；Q 弹液态玻璃底栏无回归。

## 2.2 · 滑块动画对标 Apple 液态玻璃（缩放 + 弹跳 + 高光）

- **底栏选中滑块动画重做。** 参照 WWDC25「使用全新设计系统构建 SwiftUI App」（323）对 Liquid Glass 控件的定义——玻璃通过**缩放（scale）、弹跳（bounce）、闪烁（shine）**响应交互——替换掉原先的多周期果冻式 Q-bounce。
- **克制的单次弹跳。** 切页/松手时滑块先轻微放大（scale≈1.012）、一次柔和过冲后即稳定，不再来回抖动；弹簧阻尼从 ζ≈0.28 提到 ≈0.55。
- **随动高光（shine）。** 滑块内增加一条随移动方向扫过的镜面高光带（CSS `--shine` 驱动），切页时扫到峰值再平滑归位，呈现液态玻璃的光泽流动。
- **方向拉伸。** 拖动滑块时按手指方向轻微拉伸、按力度增大（幅度收敛、单次回弹）；按住时柔和膨胀。
- **兼容与回归。** 新增 `prefers-reduced-motion` 降级；真实 Android 10 WebView 74、Chromium 88/144 验证动画曲线一致、0 JS 错误；20 项 UI 回归通过；同签名可覆盖安装。

## 2.1 · 对标 Apple 液态玻璃：更完整的透镜折射 + 可变扭曲 + 中性反射

- **还原液态玻璃的三要素：背景透镜折射、随交互变化的扭曲、中性镜面反射。** 参照 Apple WWDC25 Liquid Glass 的 lensing/specular 行为重做 SVG 滤镜链。
- **消除文字重影。** 旧实现用第二路 `feDisplacementMap in="SourceGraphic"` 做"反射"，会把导航文字整体复制位移后叠回，造成双影。v2.1 删除该合成路径：反射改由 Fresnel 权重的**中性白边缘高光**承担（`feColorMatrix` 取透镜图的 Fresnel 通道），既不复制内容、也不染任何色。
- **扭曲可见且随交互变化。** 基础位移 scale 由 48 提升到 60；拖动/拉动胶囊、拖动选中滑块、快速滚动时，`PilotGlass.frame()` 按 pull/knob/speed/scroll 实时把 scale 抬到最高 92，弯折随手势连续变化；配合胶囊的弹性拉伸（弯月形变），呈现"液态"手感。
- **高透无色。** 中心位移趋近 0，背景原样透出；玻璃本体零染色，颜色只来自被折射的真实内容；`forced-colors`、`prefers-reduced-transparency`、`prefers-reduced-motion` 均降级处理。
- **跨引擎兼容。** 场景采样在 WebView 74/87 不支持 `backdrop-filter: url()` 的老内核上走 `filter: url()` + 阴影 DOM 镜像（Chrome 19+ 即支持）；位移贴图同时写 `href`/`xlink:href`。已在真实 Android 10 WebView、Chromium 88、Chromium 144 三个内核验证：滤镜挂载、贴图生成、scale 随交互变化、0 JS 错误。
- **回归：** 20 项 UI 回归全通过；同签名证书可覆盖安装。

## 2.0 · 真机可见的真实折射 + 应用图标

- **根因修复：之前"真实折射"在用户 Android 10 / WebView 87 上从未渲染。** v1.8/1.9 依赖 `backdrop-filter: url(#glass-refract)` 扭曲背后的真实内容；但 Chromium 直到 2024 年才让 `backdrop-filter` 接受 SVG `url()` 滤镜，WebView 87（Chromium 87，2020）只会"解析但不渲染"，所以真机上一直是平的。
- **改用跨引擎的真实折射：DOM 镜像 + `filter: url()`。** 把导航栏背后的真实页面内容克隆到一个裁剪层，用 `feDisplacementMap` 位移这张镜像——`filter: url()` 从 Chrome 19 起所有引擎都支持，包括 WebView 87。镜像不透明，替换而非叠加背后内容，避免重影；随滚动、页面切换、内容变化实时同步。位移贴图 `feImage` 同时写 `href` 和 `xlink:href` 兼容旧内核。导航条自身的 CSS `backdrop-filter: url()` 改为普通亮度滤镜，避免与镜像折射叠加。
- **新增应用启动器图标。** 深青渐变 + 玻璃棱镜（与品牌一致）：各密度方形/圆形 PNG（mdpi→xxxhdpi）、108dp 自适应前景、v26/v33 自适应图标与单色图标；清单加入 `roundIcon`。
- **验证：** 高对比棋盘下端内条纹在圆角明显弯折；镜像与背后内容逐像素对齐、无重影；滚动/切页/内容更新后同步正确；既有 UI 回归与 Lint 通过；同签名证书可覆盖安装。

## 1.9 · 无色透明玻璃 + 更强折射，修复光学层被通盘清空

- **玻璃改为完全无色透明。** 用户指出"我要透明无色，怎么还整上颜色了"。移除玻璃上所有青/品红色散与冷色调：CSS 里 6 处绿色调 rgba 改为纯白/中性灰，去掉全部 `saturate()`（含 `dock-lens` 的 `saturate(120%)`）；canvas 光学层 shader 与软件路径的 R/G/B 三通道 Fresnel、色散层统一为中性单通道（R=G=B，实测通道差 0）。颜色现在**只来自被折射的真实背景**，玻璃本身不染任何色。
- **真实折射调强。** `feDisplacementMap` 的 `scale` 从 30 提到 50；多档实验（30/44/58/72）确认 50 折射明显且边缘不露白。中心 canvas 高光 alpha 压到 ~7/255，不再蒙住背后的折射内容——背后文字/条纹透过玻璃时弯折清晰可辨。
- **修复一个长期隐藏的致命 bug：光学层在真机上整层全空（alpha 全 0）。** 两个原因叠加：① 软件路径把 canvas 尺寸设成 CSS 逻辑宽（312），而 `measure()` 按 DPR 设成 546，两者每帧互相覆盖并清空画布；现改为软件路径直接使用 `canvas.width/height`。② 循环内局部变量命名 `c`/`g` 覆盖了光源向量 `a/b/c/g`，使 `soft()` 读到 undefined 分量产生 NaN，从第二个像素起整层变 NaN→透明；现改名 `lum`。此前所有"色散版"因用 `cr/cg/cb` 未触发此 bug，本次改中性时踩中并修复。
- **验证：** 用户设备 87 场景——通道差 0（无色）、中心 alpha 7（通透）、峰值 alpha 210、feScale 50、backdrop 为纯 `url(#glass-refract)` 无 saturate、高光随光照翻转、0 错误；旧引擎 74 与引擎 120 场景通过；既有 20 项 UI 回归通过；Lint 0 错误。

## 1.8 · 真正的背景折射（Liquid Glass 位移），修复真机从未启用

- **根因修复：之前几版都不是真折射，且真机上折射从未启用。** 用户上网查证后指出厂商做法；确认 Apple Liquid Glass 及所有主流网页复刻的核心是把**玻璃背后的真实内容做位移扭曲**（SDF → 法线 → IOR/Snell 定律 → `feDisplacementMap` → `backdrop-filter: url()`），而不是在 canvas 上画反光/彩边。此前 v1.5 的能力探测把**任何 Android UA 都判为 legacy**，导致 `glass-bdurl` 类永不加、真实折射分支从未执行——这正是用户反复反馈"没有折射"的直接原因。
- **改为仅把 Chromium < 76 判为不支持**。用户的 WebView **87.0.4280.101 > 76**，原生支持 `backdrop-filter: url(#svgFilter)`。现在正确启用真实折射，且 `saturate()` 保持独立声明，旧引擎失败时安全降级。
- **替换位移图为物理正确的版本**：按斯涅尔定律（IOR 1.52）、对称凸透镜压缩模型生成，位移只集中在边缘带（scale=30），中心保持清晰。端到端验证（UA 87 + 真实导航 + 高对比棋盘）：背后条纹在左右圆角与上下边缘**明显弯折/挤压**；滚动时真实文字经过导航也被折射。选中滑块为第二层折射。
- canvas 光学层继续提供镜面高光/亮唇（软件 2D 路径，绕开 WebView 的 WebGL 空层 bug），与真实折射叠加；-webgl 强制关闭逻辑沿用。
- 验证脚本 `tests/ui/verify-android10.cjs` 改为针对用户确切版本 87：断言 url() 折射已启用、位移图有效、scale 合理、无 backdrop-root 破坏，并保留 74 降级与现代引擎两场景。三场景全通过、0 JS 错误、交互回归通过、Lint 0 错误。

## 1.7 · 整面透镜折射，取代固定四边彩边

- **重做光学模型：从「边缘彩边 + 中心全空」改为「整面凸透镜」**。此前折射只画在圆角/四边的窄带（固定青/品红双描边），中心 alpha 约 1/255 完全空白，用户反馈"四边固定很难看、中间没有折射"。现把整个表面当作一个有轻微曲率的透镜：中心保留柔和tilt，能接住随光照移动的大面积反光，整块玻璃都有自然的镜面流动感。
- **色散不再固定在四边**：由"钉死在圆角的青外品红内双色带"改为"随光照漂移的柔和光谱渐变 + 极轻的边缘条纹"，边缘更干净，主视觉交给中心流动反光。
- **高光随光照移动**：叠加"覆盖全面的稳定底光" + "跟踪光源的移动高光"，实测内部面亮度重心随指针从左 `0.464 → 0.519` 移动；四种棚灯反射与焦散仍随指针/滚动/拖拽变化。
- **保持通透与可读**：中心 alpha 约 88/255（有玻璃感但不糊内容），整个面 100% 有玻璃覆盖，0 过曝，色散通道跨度 0..75（柔和）。软件路径与 WebGL shader 严格同步；安卓 WebView 仍强制软件 2D 路径（沿用 1.6 的 GL 空层修复）。
- 离线光学实验脚本 `tools/art/glass-lab.cjs` 与验证脚本 `tests/ui/verify-android10.cjs`（新增高光移动、全face覆盖、0过曝断言）。

## 1.6 · 修复安卓真机「玻璃发平、看不到折射」

- **定位到真正的真机故障根因**：此前所有光学验证都在无 WebGL 的 Chromium 里进行，测的全是软件 2D 路径；而安卓 WebView 里 WebGL 上下文能创建成功、shader 也能编译通过，但合成到屏幕的是**全透明**画面。旧逻辑只要 WebGL program 存在就永远走 GL 分支，`software()` 从未被调用，于是真机上整层折射是空白——用户看到的就是"平的、没有折射"。这是 1.5 只加能力探测却没解决的问题（1.5 在真机上依旧走 GL 空层，故"一点变化也没有"）。
- **安卓 WebView 强制软件光学路径**：新增 `forceSoftware`，凡 UA 含 `Android` 或 `; wv)` 的引擎一律跳过 WebGL 初始化，直接走已被逐像素验证能画出折射的 2D 软件路径。桌面 Chromium 仍保留 WebGL 作为加分项。验证脚本用 Playwright 钩子记录 `#dock-optics.getContext()`：安卓 UA 下实际调用序列为 `['2d']`，WebGL **从未被请求**，彻底绕开 GL 空层。
- **明显增强色散可见度**：青/品红色散带加宽、饱和度与 alpha 贡献提高（WebGL shader 与软件路径同步）。安卓软件路径实测左右圆角青色带 `b-r` 峰值 166/185、品红带 -68，肉眼清晰可辨；中心 alpha 仍为 1/255 保持全透。
- 复现脚本 `tests/ui/verify-android10.cjs` 更新为「安卓 UA + WebGL 可用」场景（正是漏测的真机条件），除降级断言外新增 GL 未调用、青/品红双色带可见的强校验。

## 1.5 · Android 10 WebView 兼容加固

- **修复老 WebView 上玻璃失去饱和度的问题**：此前 `backdrop-filter: url(#glass-refract) saturate(106%)` 把 SVG 折射与饱和度写在**同一条声明**里。Android 10 出厂 WebView（Chromium 74）能解析 `backdrop-filter` 但不把 SVG 滤镜当作 backdrop 渲染，于是整条声明被丢弃，连 `saturate` 一起失效。现把饱和度拆成独立声明——任何支持 `backdrop-filter` 的引擎都能保住通透玻璃；`url()` 折射作为加分项单独处理。
- **能力探测替代 `@supports` 门控**：新增一次性 WebView 能力探测，读取 UA 版本与 `CSS.supports` 结果，给根节点标记 `glass-probed` / `glass-legacy-webview` / `glass-bdurl` / `glass-no-bd`。真实背景位移折射只在确认支持且非旧版 WebView 时启用；`@supports` 只校验语法、无法判断能否渲染，曾导致声明被丢弃时连累饱和度。完全不支持 `backdrop-filter` 的引擎改走更清晰的渐变描边，中心保持全透。
- **不依赖 WebGL 的折射基线**：安卓 WebView 中 WebGL 常不可用或丢失，canvas 软件光学路径始终是兜底。合成层测试在无 WebGL 的 Android 10 UA 下确认：canvas 折射正常绘制（边缘含色散彩色、中心 alpha 1/255）、saturate 保留、无 `url()` 声明、0 JS 错误；滑块拖动吸附、点击切换、胶囊拖拽回归通过。
- 复现脚本：`tests/ui/verify-android10.cjs`（Android 10 WebView 74/无 WebGL 与现代引擎两套场景）。

## 1.4 · 整块通透玻璃与光学折射

- 底部导航按真实清透玻璃重做：菲涅尔反射率在正对的中心约为 4%（几乎全透，身后内容清晰可见），只有圆角斜面与光源方向出现清晰镜面高光，并保留边缘 RGB 色散。移除了会把中心蒙白的 body 基础着色与环境底光，也移除了把高光扭成波纹的 SVG 湍流位移滤镜——二者此前让玻璃显得不透明、反射发糊。
- **彻底解决「不通透」**：定位到 canvas 之外的两层 CSS 才是主因——`backdrop-filter: blur(7px)` 把身后内容糊成一团（棋盘条纹对比度从裸基准 33.7 掉到 8.7），选中滑块 94% 白的不透明药丸盖住整个标签位。现移除背景模糊（仅保留极弱 `saturate(106%)`）、把白底与选中滑块降到近乎透明；玻璃本体改由增强后的 canvas 菲涅尔边缘高光与内阴影描边来呈现，中心保持全透。量化保真度（与无遮挡棋盘的相关性）从 **0.173 提升到 0.931**。
- 反射分布：软件路径分区实测中心平均 alpha 1/255、整体平均 8，0 过曝；反射集中在掠射边缘，中心通透，边缘高光足以在浅色页面上勾勒出玻璃轮廓。
- **可见的真实折射（重做）**：前一版只靠 `backdrop-filter:url()` 位移背景——浅灰纯色背景被位移后肉眼根本看不出，等于没有折射。改为在 canvas 光学层直接绘制折射本身：圆角处**青/品红色散边**（外青内品红）、紧贴边缘的**亮唇 + 内侧暗线**（光线弯折/全反射）、底缘**焦散亮弧**，中心保持通透。这些特征由玻璃自身绘制，任何背景（含纯色）下都可见；WebGL 与软件路径同步实现。同时保留 `backdrop-filter:url(#glass-refract)` 的内联 SDF 位移贴图，在支持的 WebView 上对真实背景再叠加透镜弯折；不支持时静默退化、不影响 canvas 折射。折射色散以独立加色层与自身 alpha 输出，避免被 4% 菲涅尔衰减淹没；0 过曝、中心 alpha 1/255。
- **可拖动的玻璃滑块（力度变形 + Q弹）**：按住选中滑块可沿导航栏左右拖动（钳制在胶囊内、松手吸附到最近标签，点击切换仍正常）；滑块是叠在导航玻璃之上的第二层独立玻璃。缩放与形变随拖拽力度非线性变化——小幅拖放大约 1.15、大幅拖放大到 1.43，并沿拖动方向拉长、垂直压扁（果冻感）。双欠阻尼弹簧（ζ≈0.3）让松手明显回弹：实测 sx `1.33 → 0.87 → 1.05 → 1.0`，多次振荡后归位。**修复 bug**：命中判定改用滑块实时 `getBoundingClientRect()`（含放大后的 transform），放大状态下抓滑块边缘不再误触发胶囊形变；钳制预留放大余量，圆角不被裁切。
- 本次反馈面板新增「复制」按钮，可将结果文本复制到系统剪贴板；Web 环境不可用时回退为长按手动复制提示。
- 说明：`filter:url()` 对 backdrop 透出的 DOM 无效（已实测），`backdrop-filter:url()` 在 Chromium 144 能位移背景但 Android WebView 版本支持不一、且纯色背景位移不可见。因此折射的主视觉由 canvas 自身绘制（任何背景可见），背景位移仅作加分；透射由 backdrop-filter 负责。
